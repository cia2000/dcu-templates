# Brief del problema y del ciclo

## Finalidad

Delimita el problema que el equipo quiere comprender o resolver en un ciclo, el resultado esperado y las restricciones conocidas. Evita comenzar por una solución predeterminada.

## Guía de uso

1. Describir el problema observado y para quién supone una dificultad.
2. Formular el objetivo de aprendizaje o de producto del ciclo.
3. Anotar supuestos, restricciones y decisiones fuera de alcance.

## Plantilla

```markdown
# Brief: [nombre del ciclo]

| Campo | Contenido |
| --- | --- |
| Ciclo | [Número y fechas] |
| Equipo | [ ] |
| Problema | [Qué dificultad se quiere comprender o reducir] |
| Personas afectadas | [ ] |
| Objetivo del ciclo | [Resultado verificable] |
| Alcance | [Incluye] |
| Fuera de alcance | [ ] |
| Supuestos y riesgos | [ ] |
| Evidencia necesaria | [ ] |
```

## Criterios de revisión

- Describe un problema, no una tecnología o componente impuesto.
- Define un resultado y un alcance comprobables.
- Identifica supuestos que deberán validarse.
